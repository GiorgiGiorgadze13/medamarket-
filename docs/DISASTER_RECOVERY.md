# MedaMarket - Disaster Recovery & Google Drive Backup Runbook

This document details the automated offsite backup architecture using Google Drive via `rclone`, zero-trust AES-256 encryption, configuration requirements, and step-by-step restoration procedures.

---

## 1. Automated Backup Architecture (Google Drive)

- **Workflow:** `.github/workflows/db-backup-gdrive.yml`
- **Schedule:** Daily at `03:00 UTC` (`07:00 AM Georgia Time`) or manually via GitHub Actions `workflow_dispatch`.
- **Destination Folder:** Google Drive `/MedaMarket-Backups/`
  - `/MedaMarket-Backups/daily/` (7 newest daily snapshots kept)
  - `/MedaMarket-Backups/weekly/` (4 newest weekly snapshots kept)
- **Engine:** PostgreSQL 17 `pg_dump` with `--clean --if-exists --no-owner --no-privileges`.
- **Compression:** Gzip level 9 (`.sql.gz`).
- **Encryption:** OpenSSL AES-256-CBC PBKDF2 (100,000 iterations). Plaintext SQL is never uploaded or exposed.
- **Verification:** Automated remote size check (`rclone size`) + SHA-256 integrity checksum verification (`.sha256`).

## 3. How to Authorize Google Drive (`rclone authorize`)

To give GitHub Actions permission to upload to your Google Drive (`giorgadze111333@gmail.com`) **without sharing your Google password or adding a credit card**:

### Step 3.1: Download Rclone on your computer
1. Visit [rclone.org/downloads](https://rclone.org/downloads/) and download the standalone zip for your OS (e.g., Windows 64-bit).
2. Extract the zip file (you will see `rclone.exe`).
3. Open PowerShell or Command Prompt in that folder.

### Step 3.2: Run the Authorization Command
Run the following command in your terminal:
```bash
./rclone authorize "drive"
```
*(On Mac/Linux: `rclone authorize "drive"`)*

1. A web browser window will automatically open asking you to log into Google.
2. Select your Google account: **`giorgadze111333@gmail.com`**.
3. Click **Allow** to grant access to manage files in Google Drive.
4. The browser will say: *"Success! All done. Please go back to rclone."*
5. Return to your terminal. You will see:
   ```
   Paste the following into your remote machine --->
   {"access_token":"ya29.a0...","token_type":"Bearer","refresh_token":"1//04...","expiry":"2026-..."}
   <---End paste
   ```

### Step 3.3: Add to GitHub Secrets
1. Copy the exact text between `--->` and `<---` (the complete `{ ... }` JSON block).
2. Go to `https://github.com/GiorgiGiorgadze13/medamarket-/settings/secrets/actions`
3. Click **New repository secret**.
4. Name: `RCLONE_GDRIVE_TOKEN`
5. Value: Paste the JSON block.
6. Click **Add secret**.

> [!TIP]
> The `refresh_token` in that JSON allows GitHub Actions to automatically refresh access tokens in the background forever. You do not need to re-authenticate daily.

## 6. Disaster Recovery Restoration Procedure

> [!CAUTION]
> NEVER test restoration on your live production database! Always test against a dedicated staging database or separate Neon branch.

### Option A: Automated Staging Restore via GitHub Actions (Recommended)

You can run an automated end-to-end restoration test directly inside GitHub Actions without installing anything locally:

1. **Create an isolated Neon branch:**
   - Go to [console.neon.tech](https://console.neon.tech).
   - In your project, click **Branches** -> **New Branch**.
   - Branch name: `staging-test` (parent: `main` or empty).
   - Copy the branch connection string.

2. **Add the `STAGING_DATABASE_URL` secret in GitHub:**
   - Go to `https://github.com/GiorgiGiorgadze13/medamarket-/settings/secrets/actions`.
   - Click **New repository secret**.
   - Name: `STAGING_DATABASE_URL`
   - Value: Paste the Neon `staging-test` branch connection string.
   - Click **Add secret**.

3. **Run the manual workflow:**
   - In your GitHub repository, click the **Actions** tab.
   - In the left sidebar, click **MedaMarket Staging Restore Test**.
   - Click **Run workflow** -> **Run workflow** (leave backup filename blank for latest, or specify an exact filename).
   - The workflow:
     1. Verifies that `STAGING_DATABASE_URL` does NOT match the production database.
     2. Downloads the backup and its `.sha256` checksum from Google Drive using `rclone`.
     3. Validates the SHA-256 hash.
     4. Decrypts via AES-256 PBKDF2 (100,000 iter) and decompresses gzip.
     5. Restores into the staging branch using `psql -v ON_ERROR_STOP=1`.
     6. Queries and outputs record counts for `Category`, `InventoryHistory`, `Product`, `Sale`, `SaleItem`, and `User`.

### Option B: Local CLI Restoration via Environment Variables (Windows CMD)

Setting credentials via environment variables prevents passwords and keys from appearing in terminal history or system process lists:

```cmd
cd /d D:\Medamarket

:: 1. Set credentials in current session environment
set STAGING_DATABASE_URL=postgresql://staging_user:password@ep-staging.us-east-2.aws.neon.tech/neondb?sslmode=require
set BACKUP_ENCRYPTION_KEY=YOUR_BACKUP_ENCRYPTION_KEY

:: 2. Execute safe restore (Option A: directly from Google Drive)
node scripts/restore-database.js --from-gdrive latest --confirm-staging

:: Or (Option B: using a locally downloaded backup and .sha256 file)
node scripts/restore-database.js --backup ./backups/medamarket_20261113.sql.gz.enc --confirm-staging
```

### Linux / macOS / Git Bash Equivalent:


The script natively verifies SHA-256 integrity, decrypts (AES-256 PBKDF2), decompresses gzip, verifies safety checks, and restores the SQL schema and data cleanly.

## 7. Google Drive Storage & API Limits Consideration

1. **Storage Consumption:**
   - A single compressed and encrypted backup for MedaMarket is under 100 KB - 500 KB currently.
   - With 7 daily + 4 weekly backups (11 backups total), total storage used is **< 10 MB**, which is less than 0.1% of your 15 GB free storage quota.
2. **API Rate Limits:**
   - Google Drive allows up to 20,000 requests per 100 seconds and 750 GB of uploads per day.
   - Our workflow performs fewer than 10 API requests per day, operating orders of magnitude below all Google limits.
3. **Token Longevity:**
   - The OAuth refresh token has no expiration date unless you manually revoke it under Google Account Security settings.
